## ① 実行基盤 ― エージェントを「動かす」

<!-- セリフ：ニアのつなぎセリフをここに -->

### Runtime

エージェントを実行するサーバーレスのmicroVM環境です。

| 項目 | 内容 |
|---|---|
| コールドスタート | 約1.9〜2.0秒（V2。V1は5.4〜30秒） |
| 最大セッション時間 | 8時間 |
| ファイルシステム | セッション中は永続（再起動で初期化） |
| フレームワーク | 非依存（Strands Agents, LangGraph, カスタム等） |
| モデル | 非依存（Bedrock上の任意のモデル） |

Lambda（15分制限・ステートレス）やBedrock Agents（フレームワーク固定）では難しかった、**長時間・継続的なエージェント処理**を実現するのがRuntimeの最大の特長です。

### Harness

RuntimeでエージェントをホストするためのSDKラッパーです。エージェントのエントリーポイントを標準化し、フレームワークの違いを吸収します。エージェントのコードをAgentCoreで動かすための「受け口」と理解するとわかりやすいです。

## ② 能力拡張 ― エージェントに「できることを増やす」

<!-- セリフ：ニアのつなぎセリフをここに -->

### Memory

セッションをまたいでエージェントの記憶を永続化する仕組みです。ユーザーとの過去のやりとりや学習内容を保持し、「前回話したことを覚えている」エージェントを実現します。

### Gateway

エージェントが外部ツール・APIを呼び出すためのゲートウェイです。MCP（Model Context Protocol）サーバーへの接続を管理し、エージェントが安全に外部リソースを利用できるようにします。

### Code Interpreter

サンドボックス環境でコードをエージェントが安全に実行できる機能です。Python等を使った計算・データ処理・ファイル操作などをエージェント自身が行えるようになります。

### Browser

エージェントがWebページを閲覧・操作できる機能です。情報収集や動的なWebサービスとの連携に使います。

## ③ 認証・制御 ― エージェントを「守る・制御する」

<!-- セリフ：ニアのつなぎセリフをここに -->

AgentCoreの認証は、IAMとは**別の2つのレイヤー**が追加されており、合計3層の構造になっています。

| レイヤー | サービス | 役割 |
|---|---|---|
| 第1層 | **IAM** | AWSリソースへのアクセス制御（従来通り） |
| 第2層 | **Identity** | エージェント自身のIDとエンドユーザーの認証 |
| 第3層 | **Policy** | エージェントがどのツールを使えるかの制御 |

### Identity

エージェント自身のID管理と、エンドユーザーのOAuth認証を代行する仕組みです。「このエージェントは誰として動いているか」「このエンドユーザーは誰か」を管理します。IAMが「AWSリソースへの権限」を管理するのに対し、Identityは「エージェントとユーザーの関係」を管理します。

### Policy

Cedar言語を使って、エージェントがどのツールを呼び出せるかをポリシーとして定義する仕組みです。「このユーザーにはこのツールだけ許可する」といった細かい制御が可能です。

## ④ 運用・管理 ― エージェントを「育てる・監視する」

<!-- セリフ：ニアのつなぎセリフをここに -->

### Observability

エージェントの動作ログ・トレース・メトリクスを収集する機能です。Amazon CloudWatchと連携し、「エージェントがどう動いたか」を可視化します。

### Registry

複数のエージェントを登録・管理し、互いに発見・呼び出しができる仕組みです。マルチエージェント構成を組む際に使います。

### Evaluations

エージェントの応答品質を自動評価する機能です。正確性・安全性などの観点でスコアリングし、品質改善に役立てます。

### Optimization

エージェントのパフォーマンスを最適化する機能です。コストや応答速度のチューニングに使います。
