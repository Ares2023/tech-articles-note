# 企画: Jev を実運用に組み込んでみた（実践投入編）

## テーマ

テキストを生成しないAIモデル **Jev**（TypeSafe AI / System One）を、
実際に動いている個人サービスの夜間バッチへ組み込むまでの記録。

既存の2記事（概要・ハンズオン）に続く3本目。今回は
**「触ってみた」ではなく「実戦で使えるか実測した」** という位置づけにする。

- 対象サービス: [Mugenknock](https://mugenknock.com)（AWS認定試験の問題演習サイト・個人開発）
- 組み込んだ場所: 問題の妥当性チェックを行う夜間バッチ（`02-check-validity.sh`）
- 結論: **「確認をJev・修正をClaude」という当初構想は成立せず、用途を変えて採用した**

## ターゲット読者

- Jev の存在は知ったが「で、実務で何に使えるの？」が分からない人
- LLM のコスト・レイテンシに悩んでいて、軽量な判定モデルを検討している人
- LLM を評価する側の人（評価設計の落とし穴の事例として読める）

## この記事の売り（既存2記事との差分）

| 記事 | 内容 |
|---|---|
| 概要編（既存） | Jev とは何か・LLMとの違い・3つの質問タイプ |
| ハンズオン編（既存） | APIキー取得〜最初の呼び出し〜簡単な比較 |
| **本記事** | **実データ1,275件で AUC を測り、使える観点/使えない観点を切り分けて本番投入するまで** |

とくに他記事にない要素:

1. **失敗と却下案を全部載せる。** 最初の設計は AUC 0.425（ランダム以下）で完全に失敗した。
   AUC 1.000 が出て喜んだらラベルリークだった、という話も含める。
2. **数字が全部実測。** 公式のベンチマークではなく、自分のデータでの AUC・コスト・
   再現性のばらつきを出す。
3. **「使えなかった」を隠さない。** 当初やりたかった分業は成立しなかった。
   代わりに用途を変えて着地させた過程が本題。

## 構成案

1. 導入 — Jev を実運用に入れたくなった動機（夜間バッチがトークン律速で止まっている）
2. やりたかったこと — 「確認をJev・修正をClaude」の分業構想
3. 測ってみた — 評価の設計（ラベルの作り方・CUTOFF・AUC）
4. 失敗編
   - 曖昧な質問は機能しない（AUC 0.425）
   - AUC 1.000 の幻（ラベルリーク）
   - 質問を詰め込むと希釈される
   - SDKの制約をAPIの制約と誤認した
5. 分かった強みと弱み（実測表）
6. 結論が変わる — ゲートではなくランキングに使う
7. 実装 — 最終的な設計（優先順位・縮退・飢餓対策）
8. 効果とコスト
9. 教訓 — System One モデルの向き・不向き

## 注意点（執筆時）

- **Jev は「System One（速い直感）」というコンセプト**。この比喩を軸にすると
  強み弱みが一本の線で説明できる（直感で答えられる問い＝強い／熟考が要る問い＝無理）。
- 数字は `01_調査/調査結果まとめ.md` が正。記事に書くときはそこから引く。
- 実装コードの引用は最小限にする（本題は評価と意思決定であってコードではない）。

## 追記（2026-09-30 追試後）

上の企画は第1ラウンド（n=45）時点のもの。その後の追試で次の点が動いた。

- **結論の更新**: 「用途を変えて採用した」は、追試で**静的な1行ルールでもほぼ同じ運用結果が出る**と分かり、
  採用を続けるかは未決定。Jev が本物の強みを持つのは「正当な括弧 対 ヒント漏れ」の切り分けだが、
  現行の運用設定では欠陥検出数にほとんど出ない。
- **記事の軸の更新**: 「新しい道具を試したら役に立った」ではなく、「道具を外しても同じ結果が出るか」まで
  確かめた話にできる。詳細は `01_調査/調査結果まとめ.md` §7「追試後の軸」。
- **売りの追加**: 「失敗と却下案を全部載せる」に、**自分の提案を疑って静的解析と再比較した**過程が加わる
  （最初の正規表現との比較は素朴な版が相手だった）。「使えなかった」だけでなく
  「使えたが必須ではなかった」も書ける。
- **数字は訂正後を使う**: hint_leak の AUC は 0.901 ではなく 0.82、費用は $0.0003/問。
  訂正の一覧は `01_調査/調査ログ.md` 末尾「訂正の一覧」。
- **注意**: 静的に置き換えるか Jev を残すかが決まるまで、記事の「採用した」という表現は避ける。
- **構成案9「System One モデルの向き・不向き」**: `01_調査/調査結果まとめ.md` §6c を元にする。
  実測・実感・推測を区別し、LLM との比較が未実施である点を但し書きとして必ず入れる。
